Hey Rex,
For your feedback you asked if you should try and get a working demo out or work on the multiplayer aspect like it is a full game. Initially I was going to say you should build it out like a full game, but I think it would be best to ask first.
What do you want this project to be?
Do you want it to be a part of your portfolio, something a potential employer can look at to see who you work or a fully playable demo that can be turned into a game later on?
If this project is meant to be a part of your portfolio I was argue for making it a functional demo first, it doesn't need to be scale if it just a portfolio piece. Not only that but it shrinks the scope considerably as if things don't need to scale they can be janky, if you are familiar with the first iPod showcase think of that and if not here is an article on it https://finance.yahoo.com/news/steve-jobs-rigged-first-iphone-152527272.html . However if it is meant to be a demo that can later be turned into a full game later on then build it out properly. 
One thing to remember is that completing the project isn't the most important part of working on it, the lessons and achievements you learn along the way are. I have been meeting with Prof Krause every week (as they are my client) and the main takeaways I get from each meeting are always lessons I have learned from the project, so even if you spend a whole sprint just fixing bugs think about how you went about it. Turn your problem into a story for the future about how you solve problems with no external guidance.
